# telebeland — frontend

React 19 + TypeScript (strict) + Vite 8, Tailwind CSS 4, shadcn/ui (Radix),
React Router 8, TanStack Query 5, React Hook Form + Zod, Lucide.

## Запуск

Нужен Node ≥ 22.12 (проверено на 23.6). Для установки зависимостей
используйте npm ≥ 12: npm 11.5 падает с `Cannot read properties of null
(reading 'edgesOut')` на peer-зависимостях vitest.

```bash
cd frontend
npm ci            # или: npx npm@latest ci
npm run dev       # http://localhost:5173
```

Backend должен работать на `http://localhost:8080` (или задайте
`API_PROXY_TARGET`, см. ниже) с `PUBLIC_ORIGIN=http://localhost:5173`.

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Dev-сервер с прокси `/v1` на backend |
| `npm run typecheck` | `tsc -b` в strict-режиме |
| `npm run lint` | ESLint (typescript-eslint, react-hooks) |
| `npm test` | Vitest: HTTP-слой и CSRF, безопасный return URL, правила вопросов, черновик импорта, очередь сохранения ответов, серверный таймер |
| `npm run build` | Проверка типов и production build в `dist/` |

## Настройка backend для работы через frontend

Браузер обращается только к origin frontend. Dev-сервер проксирует `/v1`,
`/health`, `/ready` на Go backend без изменения пути и заголовка `Host`. Через
прокси идут и HTML-страница подтверждения email, и Google OAuth.

| Настройка | Значение |
| --- | --- |
| Адрес приложения | `http://localhost:5173` |
| Цель прокси: `API_PROXY_TARGET` в env frontend (`.env.local`) | по умолчанию `http://localhost:8080` |
| `PUBLIC_ORIGIN` в backend `.env` | `http://localhost:5173` |
| `GOOGLE_REDIRECT_URL` в backend `.env` | `http://localhost:5173/v1/auth/google/callback` или пусто |
| Authorized redirect URI в Google Cloud | `http://localhost:5173/v1/auth/google/callback` |

- Без `PUBLIC_ORIGIN=http://localhost:5173` backend отклоняет все изменяющие
  запросы с `403 untrusted request origin`. Ссылки в письмах строятся от этого же адреса.
- Backend проверяет, что `GOOGLE_REDIRECT_URL` равен `PUBLIC_ORIGIN` +
  `/v1/auth/google/callback`. Если оставить `GOOGLE_REDIRECT_URL` на порту 8080
  и сменить `PUBLIC_ORIGIN`, backend не запустится.
- В `docker-compose.yml` по умолчанию `PUBLIC_ORIGIN=http://localhost:8080`.
  Для работы через frontend задайте его в `.env` и пересоздайте контейнер `app`.

### Google-вход

Кнопка — обычная ссылка на `/v1/auth/google/start` (навигация браузера, не
`fetch`). Перед переходом frontend сохраняет в `sessionStorage` путь, куда
вернуть пользователя. После успешного callback backend отвечает `303` на
`/auth/complete`. Эта страница загружает профиль, очищает кэш прошлого
пользователя и возвращает в приложение. При ошибке callback backend
по-прежнему показывает JSON `{"error": "..."}`.

## Как устроено

**Маршруты.**

- Публичные: `/login`, `/register`, `/check-email`, `/auth/complete`.
- Остальные требуют сессию:
  - `/` — кабинет;
  - `/banks`, `/banks/:id` — банки и вопросы;
  - `/import` — импорт DOCX;
  - `/quizzes`, `/quizzes/new`, `/quizzes/:id` — тесты;
  - `/attempts/:id/result` — результат;
  - `/attempts/:id` — прохождение, полноэкранный режим без навигации приложения.

  Каждая страница — отдельный chunk.

**Сессия.**

- Session cookie выставляет backend (HttpOnly). CSRF-токен хранится только в
  памяти: запрашивается при первой изменяющей операции и после входа запрашивается
  заново. Если backend отклоняет токен (`403`), frontend один раз берёт новый и
  повторяет запрос. Это безопасно даже для создания: backend отклоняет запрос до обработчика.
- Любой `401` защищённого запроса завершает сессию локально. После этого открывается
  `/login?next=…` с подсказкой «Сессия закончилась». Return URL принимается
  только как путь этого приложения: не `//host`, не `/v1/...` и не страницы входа.
- Вход, выход и Google-callback очищают кэш запросов. Если `/auth/me` вернул
  другого пользователя, например после входа в соседней вкладке, данные прошлого
  пользователя удаляются.

**Повторы.**

- Чтения при сетевых и 5xx-ошибках повторяются до двух раз.
- Создание банка, вопроса и теста, регистрация, подтверждение импорта и старт
  попытки автоматически не повторяются. Кнопки блокируются на время запроса.
- При обрыве связи на создании показывается предупреждение: результат неизвестен,
  проверьте список, прежде чем отправлять снова.
- Ответы попытки (`PUT`, идемпотентно) повторяются автоматически. Перед завершением
  попытки frontend дожидается всех сохранений.

**Импорт DOCX.** Перед сохранением черновик проверяется по тем же правилам, что
и ручное создание вопроса:

- текст не пустой;
- не меньше двух вариантов;
- варианты не пустые и не повторяются без учёта регистра;
- правильный вариант ровно один.

Backend при `POST /imports` эти правила не проверяет (см. ниже).

**Тексты** лежат в `src/i18n/ru.ts`. Этот файл задаёт форму словаря: будущий
`az.ts` типизируется как `Messages` и регистрируется в `src/i18n/index.tsx`.

## Демо (только dev)

`http://localhost:5173/demo` — кабинет, прохождение и результат на
in-memory API, без backend. Удобно для проверки состояний: таймер на 40 секунд,
сбой сохранения, пустой кабинет. В production-сборку демо не входит.

## Замечания по backend

- `POST /v1/question-banks/{id}/imports` сохраняет черновик без проверки: можно
  записать вопрос без текста или без правильного ответа. `docs/api.md` обещает
  `400`. Frontend закрывает это своей проверкой, но для других клиентов
  проверку стоит добавить на сервере.
- Отдельного списка активных попыток нет. Кабинет запрашивает последнюю
  попытку для каждого из 5 последних тестов, список тестов — для каждой строки.
- У теста нет названия, показывается название банка.
- Страница подтверждения email (`GET /v1/auth/verify-email`) отдаётся
  backend. После подтверждения на ней нет ссылки на вход, и она называет
  приложение «Question-To-Quiz».

## Структура

```
src/
  api/          HTTP-клиент (cookie-сессия, CSRF, классификация ошибок), endpoints, типы, query keys
  app/          роутер, корневой провайдер с обработкой 401, построители путей
  components/
    ui/         примитивы shadcn/ui в оформлении telebeland
    layout/     оболочка приложения, навигация, реестр инструментов
    common/     состояния, формы, диалог подтверждения, уведомления
    brand/      логотип и иллюстрации
  features/     auth, dashboard, banks, import, quizzes, attempt, result
  i18n/         тексты и плюрализация
  demo/         in-memory API для /demo (dev)
  styles/       дизайн-токены в @theme (контраст каждой текстовой пары указан в комментарии)
```

Будущие инструменты («Тест по учебной теме», «Презентация по теме») описаны
в `components/layout/navigation.ts`. Чтобы включить инструмент, задайте ему маршрут.
